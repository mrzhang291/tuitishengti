# Smart Question Recommender

## 产品边界

严格区分两种模式，不要混用：

1. **原题错题集**：根据班级作答记录筛选题库原题，供订正、讲评和打印。该模式明确允许学生再次看到原题。
2. **智能新题**：默认先按知识点建立教学链，再按题型和难度生成；教师切换“按学情生成”后，学生作答只作为可选加权层，不改变知识点教学链的主入口。教学链按 `prototype_consolidation -> method_variant -> transfer_variant` 组织题位：先巩固原型，再做同法变式，最后做迁移提升。每道新题只允许一个结构锚点：单一道安全母题或一个安全蓝图。教学证据、诊断证据与结构锚点只在教师端出现。

不要把原题错题集包装成“新题生成”。不要在个性新题页面展示空白录题表单。

## 必读资源

- 修改或执行个性新题、智能推题、实时生题、难度判定、结构去重、教师反馈闭环时，先读 `references/ai-native-quality-workflow.md`。
- 校验字段、产物结构或数据兼容性不清楚时，读 `references/data-contract.md`。

## AI-native 推题原则

- 先按知识点建立教学链，再诊断训练目标、规划任务、生成题目。不要先寻找学生画像，也不要只按规则分数从安全题池挑一个母题就开始改写。
- 诊断输出必须区分 `knowledge_gap`、`method_gap`、`error_pattern`、`transfer_gap` 和 `target_question_type`；按知识点生成时这些字段来自题库教学证据，按学情生成时才叠加真实学生作答。
- 每个生成任务必须有可审计任务单：目标知识点、目标题型、精确 `target_level`、方法族、函数族、至少两个变化维度、禁止结构、最低复杂度信号、诊断证据数量和唯一结构锚点。
- 后端必须真实消费 1-5 级难度，不得只把 4级/5级合并为 `challenge`。基础公式求导最高 2级；参数/区间/多结论判断通常为 4级；只有恒成立、存在性、范围证明、多问联动、高阶或辅助函数分析中至少三类复杂度信号才可通过 5级。
- 每道新题保存 `generation.pedagogical_fingerprint`，用于教学结构去重。文本不同但同属“基本函数求导 + 单选 + 直接套公式”的题，必须判为同类型重复。
- 离线教学链候选必须保存 `generation.recommendation_score`，分数由题源安全分、教学链阶段匹配分、难度匹配分、结构新颖分和教师反馈惩罚组成；排序只用于教师端预览和任务单规划，不代表实时生成已经通过。
- 新题必须经过双审题：数学正确性与答案解析一致性审题、教学质量二审。二审估计等级与目标等级不一致时不得进入教师通过状态。
- 教师反馈必须成为记忆：`解析错误`、`难度偏低`、`难度偏高`、`结构重复` 等反馈写入 `generation/teacher_quality_feedback.jsonl`，后续规划和生成必须避开对应负样本。

## 必需输入

确认结构化题库至少包含：

- `tags/all_question_tags.json`
- `questions/<question_id>/` 下所引用的资源

以下学生/班级数据只在原题错题集、错误率排序或“按学情生成”时需要；按知识点生题不得因为缺少学生数据而停止：

- `student/question_performance.json`
- `student/student_exam_records.jsonl` 或开发期的 `student/simulated_student_records.jsonl`

所有推荐命令必须显式接收当前结构化题库目录。`references/data/` 仅是回归测试夹具，任何入口都不得在缺少用户数据时自动回退到该示例题库。

按需读取 `references/data-contract.md`。

## 原题错题集流程

1. 用班级真实作答记录统计答对、答错、未作答和正确率；`attempted: false` 不算答错。
2. 从安全题池按答错人数、正确率、题型、知识点、来源多样性和标签可靠度筛选原题。
3. 用 `scripts/assemble_class_paper.py <structured-dir>` 生成错题集候选与备选。
4. 在教师工作台“原题错题集”页直接展示原题、原答案和解析，并允许按题型、知识点、错误率层级和分值换题。
5. 学生版打印原题；教师版附原题答案与解析。不要运行新题审核门。

运行 `scripts/initialize_generation_workspace.py` 时，班级生成计划、班级生成题和班级生成候选必须标记为不适用并保持空；知识点教学链、可选个人诊断、任务单与结构锚点计划继续进入新题生成链路。`student_mother_question_plans.json` 是兼容文件名，不代表新流程仍由学生计划或一批母题共同生成。

默认可沿用 60 分钟、100 分结构，但教师可以调整题型数量和知识点。产物必须标记 `artifact_role: source_wrong_question_set` 或等价明确名称，避免与生成新题混淆。

## 智能新题流程

严格按以下顺序执行：

1. **选择生成方式**：默认使用“按知识点生成”，不要求选择学生；需要个性化时再切换“按学情生成”，按学生真实作答、近期错题、题源质量和教师反馈记忆给教学链加权。
2. **构建知识点教学链**：每个知识点先生成独立的 `knowledge_practice` 槽位，覆盖原型巩固、同法变式和迁移提升；题型、难度和训练侧重由教学目标决定，不由某个学生决定。候选池阶段必须同时计算 `pedagogical_fingerprint`、`estimated_level`、`difficulty_matches`、`recommendation_score` 和 `candidate_ranking`，把不匹配的缓存题标为需要实时换结构，而不是硬标通过。
3. **AI 诊断**：从安全题、题库标签、解法信号、近期作答、历史错因和教师反馈中提取 `knowledge_gap`、`method_gap`、`error_pattern`、`transfer_gap`、已练题型和证据置信度。按知识点生成时使用题库教学证据；按学情生成时再追加学生作答证据。诊断可以使用多题，但只产出结构化摘要；不得把多道原题全文拼进生题提示。
4. **AI 训练规划**：为每个题位明确教学链阶段、目标题型、精确 1-5 级 `target_level`、训练侧重、方法族、函数族、推理目标、最低复杂度信号、禁止结构和至少两个实质变化维度。4级和5级必须由不同硬规则判定，不能只写 `challenge`。
5. **形成出题任务单**：任务单由 Skill 生成并校验，不让模型自行猜测训练目标。任务单必须保存到 `generation.task_spec`，包含诊断摘要、目标等级合同、教学结构去重要求和教师反馈负样本。
6. **选择单一结构锚点**：每个题位只选单一道安全母题，或一个已证明的安全蓝图，用来限定结构骨架。其他诊断题只保留为诊断证据，不参与题干拼接。锚点为原题时必须通过题面-答案-解析一致性门并记录选择理由、教学结构指纹；锚点为蓝图时必须记录蓝图族。
7. **独立生成**：Cherry Studio 起草时只接收任务单、诊断摘要和一个结构锚点；禁止同时输入多道原题全文。安全蓝图可以直接构造草稿，但仍必须走 Cherry Studio 独立求解。
8. **新颖性检查**：与结构锚点、全部诊断证据、同批新题、历史题、安全题池和教师反馈负样本比较，拒绝原文复制、同义改写、只换数字、只换名称、选项平移、解题对象完全相同、教学结构指纹重复的题。
9. **独立求解**：校验模型只看新题题面，不看任务单答案、锚点答案或首次结论；重新求解后再核对答案解析、边界、定义域、选项唯一性和步骤完整性。
10. **教学质量二审**：独立求解通过后，再评估 `estimated_level`、`complexity_signals`、`pedagogical_fingerprint`、`duplication_risk` 和 `training_value`。目标 5 级但二审估为 1-3 级，或目标 4 级/5 级结构重复时，必须拒绝并换结构。
11. **实时通道**：兼容候选池只作为旧数据读取和迁移来源，不进入活跃生成区、校验计数或试卷。教师开始生成后必须走实时服务链路，不得把缓存候选伪装成本批次结果。
12. **装载等待题位**：打开教师工作台时显示明确的“等待实时生成”题位，不装载缓存题，不显示空白录题表单。
13. **教师控制**：允许选择知识点、题型、精确 1-5 级目标等级、训练侧重和生成数量（1/3/5），并支持实时重新生成单题或整套。诊断证据量由系统按题库教学证据和可选作答证据自动选择并只读展示；旧界面的 `reference_count` 仅映射为诊断证据量，不能决定向模型发送几道原题全文。
14. **教师审核与交付隔离**：换题或修改条件后自动撤销旧审核。只有 `teacher_review.status: approved` 且双审题通过的新题可以打印；学生练习只含新题，教师记录可保留教学链阶段、诊断摘要、任务单、单一结构锚点、教学质量二审和教师反馈。

运行：

```powershell
python scripts/recommend_structured_bank.py "<structured-dir>"
python scripts/initialize_generation_workspace.py "<structured-dir>"
python scripts/generate_personalized_candidate_pool.py "<structured-dir>"
```

### Cherry Studio 实时生成连接

Skill 是本地工作流、脚本与页面资源的编排包，不是 Cherry Studio 提供的可直接调用接口。运行时由工作台调用 Skill 包内的 `review_server.py` 和 `live_personalized_generation.py`；脚本再调用 Cherry Studio 企业版 API 服务器。工作台不得直接从浏览器携带密钥调用模型。

普通题固定调用链为：`HTTP 教师工作台 -> 本机 review_server.py -> Skill 内生成脚本 -> Cherry Studio 模型起草 -> 草稿立即回显 -> Cherry Studio 独立复核 -> 硬校验 -> 教师审核`。安全蓝图题固定调用链为：`HTTP 教师工作台 -> 本机 review_server.py -> Skill 安全蓝图构造题面 -> Cherry Studio 独立复核 -> 硬校验 -> 教师审核`。

两条调用链都必须先完成 `知识点教学链 -> 多题诊断 -> 出题任务单 -> 单一结构锚点`。普通模型起草只能看到任务单、诊断摘要以及一份母题全文；安全蓝图路径只能看到任务单、诊断摘要和一个蓝图。不得向起草模型同时发送多道诊断原题全文。独立复核只能看到新题题面，不得看到母题答案、蓝图证明答案、任务单预期答案或上一次复核结论。

1. 在 Cherry Studio 企业版右上角设置中打开“API 服务器”，确认状态为“运行中”，并取得 API Key。
2. 使用 Cherry Studio `/v1/models` 返回的完整模型 ID，格式通常为 `providerId:modelId`。
3. 在启动工作台的同一个 PowerShell 会话设置环境变量并运行本机服务：

```powershell
$env:CHERRY_STUDIO_BASE_URL = "http://127.0.0.1:24333"
$env:CHERRY_STUDIO_API_KEY = "<gateway-api-key>"
$env:CHERRY_STUDIO_MODEL = "<providerId:modelId>"
python "<smart-question-tagger>/scripts/review_server.py" "<structured-dir>" --open
```

Cherry Studio 企业版当前默认端口为 `24333`；若实际“API 服务器”页面显示其他地址，以页面为准并覆盖 `CHERRY_STUDIO_BASE_URL`。`CHERRY_STUDIO_TIMEOUT_SECONDS` 可选，默认 60 秒。网关地址只允许本机回环地址。API Key 只能存在于进程环境变量或 Windows 当前用户环境变量，不得写入 HTML、localStorage、题库文件、生成历史、日志或导出内容。生成器在 Windows 上允许从 `HKCU\Environment` 读取上述用户环境变量，以便双击无密钥启动脚本后仍能连接。

教师必须通过 `http://127.0.0.1:8765/review/index.html` 使用实时功能。直接双击 `review/index.html` 只进入静态预览：隐藏所有生成按钮，将“检测连接”替换为“打开实时工作台”，点击后跳转到 HTTP 服务，不得让静态页面尝试相对 `/api` 请求或汇报 5 道生成失败。题库根页的工作台入口也必须指向该 HTTP 地址。

本机服务对工作台 HTML 必须返回 `Cache-Control: no-store`，保证重建页面后普通刷新即可拿到新版本，不得让旧界面长期停留在浏览器缓存中。

可在题库根目录提供不含 API Key 的 `启动教师工作台.cmd`，只负责运行 `review_server.py --open`。若服务已经运行，同一入口应直接打开现有工作台。

每次实时生成先取得草稿；草稿返回后必须立即显示“正在独立校验”，再把新题题面交给 Cherry Studio 独立审题。选择 3/5 道表示目标交付数量，不是“最多可能得到”的数量；不得把 1–2 道成功伪装成整批完成。

实时批次必须遵守以下稳定性合同：

- 每个题位从开始到结束共享 **5 次总预算**，恢复轮不得重置次数。第 1–3 次属于初始生成，第 4 次属于第一轮结构补位，第 5 次属于第二轮结构补位；第 5 次仍未通过即为该题位最终失败，禁止再开启隐藏重试或无限循环。
- 同时最多处理 2 个题位。3 题整批的硬截止为 150 秒，任何整批的硬截止最高 180 秒；到期后立即停止新请求并结算当前结果，不得让页面长期停在“生成中”。
- `pending` 表示仍在生成、校验或等待补位，绝不能提前计入 `failed`。只有总预算耗尽、硬截止到期或出现不可重试错误时，才显示最终失败；页面应同时显示已通过、校验中、待补位和最终失败数量。
- 根批次负责整轮生命周期；停止根批次时必须同时取消它派生的所有补位子批次。取消后不得继续写历史、启动复核或在后台悄悄生成。
- 每个题位独立交付：草稿通过 Cherry Studio 独立求解和本地硬门后，立即把该题位从 `pending` 提交为 `committed` 并保留。提交接口必须支持 1–5 道子集且可安全重试；瞬时同步失败时在浏览器标记“待同步”并有限重试，不得把已通过题误判为校验失败。任一题位最终失败、超时或用户停止时，只清理仍为 `pending` 的草稿并恢复该题位生成前的旧题；已经提交的其他题位不得撤回。页面必须如实显示“已保留 N/M，K 道待补齐”，不能把部分结果冒充整批完成，也不能重复显示“结果已撤回”。
- 只有 `delivery_status: committed` 的新记录才参与全局去重。历史兼容记录若缺少 `delivery_status`，仅在 `teacher_review.status: approved` 时视为已交付；旧的待审核题和开发测试记录不得永久耗尽安全结构族。
- 草稿返回后、调用独立审题前先执行题型结构闸门。教师选择解答题时，题面不得出现 A/B/C/D 选项、选择题括号或“下列说法正确的是”等选择题句式；选择题必须有完整选项，填空题必须有明确作答空位。题型不符时直接返回该题位重试，不浪费一次独立审题调用。
- 草稿若声明“等号在 `x=c` 处成立”，本地硬门必须先把可安全解析的一元初等函数直接代入该点；函数值与不等式边界不相等时立即返回可读的反例，不得因为模型把它判成 `passed` 就放行。无法可靠解析的复杂式不猜测，继续交给独立求解。
- 独立解析出现“重新分析、重新审视、此前误算、修正为”等试错或自我纠错痕迹时，即使 `status=passed` 也必须重做；交付解析只能保留一次连贯的最终推导，禁止把模型思考过程显示给教师或学生。
- 后端对一次草稿或一次校验内部的原始请求、JSON 修复和字段补全共用同一个阶段总截止；该截止必须早于浏览器单次请求截止，使服务端先返回可处理结果，而不是浏览器先断开后又重复发起请求。
- 所有真实失败都必须返回教师能看懂的阶段与原因，例如“Cherry Studio 未连接”“模型返回内容不完整”“题型与所选解答题不符”“独立求解答案不一致”“与本批次题目结构重复”或“本批已达到时间上限”。不得只显示“全部被驳回”“JSON 不正确”或一直停留在生成中。

结构补位必须换用低歧义、闭式可验证、驻点与边界可精确求出的新结构，禁止复用失败题或只换数字。重试请求同时携带失败原因和上一道未通过题干；新的 `recipe_id` 必须以不同数学对象、条件变换和证明路径重新分配，不得拿同一配方再次碰撞。失败草稿的题干、数字无关完整结构和公式结构必须进入拒绝记录；以后任意批次再次命中时在草稿阶段直接拒绝，不能因换了批次标识就遗忘。

同一批次的 3–5 道题必须共享 `batch_id`。按 `slot_index` 分配不同的结构变化方向，并在服务端用带锁的批次草稿池检查题干相似度；普通题与同批已返回题相似度 `>=0.82` 时立即拒绝并自动重试。安全数学骨架还要携带函数族结构键：同一批次同函数族直接拦截，防止三题只换数字；不同函数族使用更严格的近完全重复阈值，避免把“句式相同但函数结构不同”的题误杀。历史校验必须额外生成“忽略数字的完整结构指纹”和“忽略数字的公式结构指纹”；任一指纹与同学生、同知识点、同题型历史题一致时，明确判为“仅替换数字或表面措辞”并拒绝。草稿进入独立校验前只作为临时占位：校验失败或硬门禁失败时必须立刻释放该题位，校验通过后才继续保留，避免废弃草稿阻塞自动补题。不要只依赖历史文件去重，因为并发请求可能在任何一题写入历史前同时开始。

生成结构指纹前必须剔除 `\left`、`\right`、`\displaystyle`、`\quad` 等纯排版命令，并把 `\dfrac`、`\tfrac` 归一为 `\frac`。同一公式只改变括号大小、分式样式或空白时必须视为同一结构，不能冒充新题。

规范化模型答案字段：删除开头的“答案：”“标准答案：”“答：”、Markdown 加粗、代码围栏和外层数学定界符；保存纯答案内容。题干、答案和解析遇到 `\frac`、`\sqrt`、上下标、花括号、函数式或带等号/不等号的裸 LaTeX 时，页面必须在不破坏已有数学定界符的前提下补 `$...$` 后再交给 MathJax；连续等式或不等式必须作为完整公式链一次性包裹，例如 `h(x)=[...]/3-\ln x=(...)/3-\ln x` 和 `0<x<1`，禁止只渲染左侧 `h(x)` 而把等号及右式留在普通文本中。左侧题卡、右侧预览、编辑即时预览和打印必须使用同一格式化规则，禁止展示 `**答案：**-\frac{5}{2}`、`h'(x)=2e^{2x}-x` 等未渲染源码。

选择题答案必须规范为 A–D 字母集合：单选题恰好 1 个字母，多选题至少 2 个字母，且 A/B/C/D 四个选项必须完整、非空、互不重复。独立解析必须以与 `answer` 完全一致的“故选 X”结论收尾；答案字段与解析最终结论矛盾时直接拒绝。非选择题先做安全的数学等价归一：`a=1`、`a≤1`（题目求最大值）、`a∈[0,1]`、`1/2`、`0.5`、`\frac12` 以及 Unicode/LaTeX 的 π、根式和幂次写法可在边界方向与结构一致时视为同一答案；不得只做字符串逐字比较，也不得把 `a≤1` 与 `a≥1` 误判为相同。普通模型草稿的出题答案与第一次独立求解不一致，但题面本身完整可解时，启动第二次不携带出题答案和首次结论的独立裁决；只有两次独立答案一致且解析内部一致时，才以独立答案纠正草稿答案，并记录 `generation.draft_answer_corrected: true` 与 `verification.consensus_checks: 2`。对“不等式证明/构造函数 + 解答题”的自由模型草稿，即使第一次独立答案碰巧与草稿一致，也必须强制再做一次不携带前次结论的独立求解；两次不能达成一致就换结构。安全蓝图仍必须由 Cherry Studio 真正独立求解；第一次返回 `failed`、漏字段、答案与解析自相矛盾或与已证明答案不一致时，允许最多再发起两次不携带蓝图答案的全新独立求解。只有某次返回 `passed`、内部一致且答案与蓝图数学等价才放行，并如实记录 `verification.consensus_checks`；若独立答案一致但模型解析夹带“重新审视”等试错叙述，用蓝图中已证明且无试错痕迹的正式解析收口，不能因展示瑕疵浪费正确题。三次都未确认时换结构重试，禁止在答案未确认时直接绕过 Cherry 校验。

调用 Cherry Studio 聊天补全时必须请求 `response_format={"type":"json_object"}`。解析模型 JSON 时允许修复数学内容中的未转义 LaTeX 反斜杠和对象末尾多余逗号；若响应因长度上限截断或修复后仍不能解析，后续请求不得原样重做整个出题任务，而要把原始响应及上一轮修复片段一起交给“JSON 截断修复器”，保持已生成题干与答案、把解析压缩到 350 个中文字符内并闭合完整 JSON，使用更低温度和 3000 token 预算。允许最多两轮紧凑修复（原始请求加修复共最多三次网关调用）；浏览器单次 API 等待窗口必须覆盖完整修复链，不能在服务端仍修复时提前断开。浏览器收到非完整服务端 JSON 时要返回明确的可重试原因，并继续当前题位的结构重试，不能直接结束整批。JSON 可解析但漏掉题干、选项、答案或解析时，必须再调用一次题目补全请求，补全后重新执行完整性门禁；独立审题返回 `failed` 且答案为空是正常失败，不得误报为“新题、答案或解析不完整”。所有格式补救都失败时再向页面返回明确的上游格式错误，不要因 `\ln`、`\frac` 等常见公式转义问题直接浪费整个批次。
对模型偶发使用的等价字段名做收口归一：`stem/question` → `stem_markdown`，`correct_answer/final_answer` → `answer`，`solution/analysis/explanation` → `solution_markdown`，布尔 `valid` → `passed/failed`；归一后仍缺少题面或独立答案才判失败。
对服务端已证明过的安全数学骨架，`draft` 阶段先汇总同一学生、同一知识点、同一题型在全部题位已经使用的函数族，再以 `(diversity_round - 1) * batch_size + slot_index` 为本题位轮换起点，沿函数族顺序取得第一个未被历史、失败记录或同批其他题位占用的结构；不得在过滤后再次按 `slot_index` 偏移，否则会跳过可用结构并过早回退自由生成。随后仍必须调用 Cherry Studio 独立复核。再次生成必须切到全局未使用的结构族，不得沿用当前骨架只换系数；安全族全局用尽，或结构指纹已使用时，跳过蓝图并调用 Cherry Studio 从零起草结构新题。网络错误、独立审题失败、答案不一致和硬门禁失败均不得绕过。生成记录必须写入真实的 `generation.draft_source`、`generation.generator`、`generation.model_role`、`generation.diversity_round` 和 `generation.structural_novelty`；页面必须分别显示“Skill 安全蓝图 → Cherry Studio 独立校验”“结构换题 → Skill 新函数族 → Cherry Studio 校验”或“结构换题 → Cherry Studio 起草与校验”。
若安全骨架的独立复核明确返回 `passed` 且给出一致答案、但漏掉解释字段，可沿用骨架中已经证明过的严格解析；不得在独立答案缺失或状态非 `passed` 时使用该回退。

诊断证据、结构锚点与新题目标题型必须彻底解耦：`source_question_type` 只描述旧参考槽位或诊断题属性，教师选择的 `target_question_type` 才决定新题形式。安全蓝图矩阵只是稳定加速路径，不是题型能力上限；找不到同题型蓝图时，应从同知识点安全题池选择一道人为可解释的结构母题，把任务单、诊断摘要和这一份母题交给 Cherry Studio 从零起草所选题型，再走独立求解和本地硬门禁，不能返回 422，也不能偷偷改回母题题型。当前各知识点默认开放单选、多选、填空、解答四种目标题型；确有教学上不适用的组合时，必须由显式能力表隐藏并说明原因，禁止根据缓存候选、诊断题或母题题型推断能力。“智能匹配”优先从当前知识点已有严格构题与校验能力的不同题型中循环分配；不等式证明默认依次使用单选、解答、填空，避免把整批交给尚无精确结构的题型碰运气。教师显式选定题型时整批必须保持该题型，不能静默替换。

精确蓝图快路径当前包括：基本函数求导/单选、构造函数证明不等式/单选、解答与填空、全概率公式/单选、求切线/单选、奇偶性与周期性/单选、平均与瞬时变化率/单选、求最值/填空、求极值与最值/单选、多选、填空与解答、判断单调区间/填空、函数零点个数/解答、期望与方差/解答。不等式单选维护 35 族，不等式挑战解答与挑战填空各维护 12 个数字无关结构互异的精确证明族，单调区间与极值多选各维护 20 族，其余组合各维护 10 类精确结构；这些数字只表示快路径储备，不限制公开题型。任意组合至少前 5 族的数字无关完整结构必须互异。单调区间必须明确区分自变量、参数和函数整体性质；极值多选必须至少两个正确项并逐项核对；非选择题必须给出唯一答案和完整推导。同一批次按 `slot_index` 分配不同函数族，教师再次生成时提升 `diversity_round` 并避开全局已用族。安全结构一旦被 Cherry 或硬校验拒绝，拒绝记录必须保存 `safety_blueprint_family`、完整结构、公式结构和 `verification_policy_version`；同一校验策略下以后自动跳过该族，同一题位的后续尝试不得连续验证同一道失败题。校验职责或答案等价规则升级后，旧版失败记录继续保留审计，但不得永久耗尽新策略下已经修正的蓝图。严格结构族全局用尽后，不得重新轮播；按轮次与题位从“数学对象 × 条件变换 × 证明路径”的动态结构配方中分配 `recipe_id`，把配方、近期通过题和失败题一并交给 Cherry Studio 起草。安全骨架与自由起草两类路径最终都必须由 Cherry Studio 只看题面独立复核并通过历史结构硬门。

全概率公式的同步/挑战解答题必须使用知识点专属动态配方，形成“第（1）问求全概率 → 第（2）问使用前问结果求后验概率或反推参数”的两问联动，禁止只生成一步加权求和。对于题面给出固定来源占比和固定条件率的题，后端同时兼容“逐来源交替叙述”和“占比分别为/条件率分别为”两种中文写法；从模型题面解析分支后使用 Python `Fraction` 重算总概率与后验概率，并以精确分数封口答案和解析，再交 Cherry Studio 独立审题。最终记录必须写入 `generation.deterministic_probability_check.method: fraction_branch_recalculation_v1`。解析器无法严格识别的变量先验或非标准结构不得猜测或强改，继续走模型独立求解与硬门；任何近似小数、分支和不为 1、或精确重算不一致都不得交付。

难度是可执行合同，不是显示标签。巩固题聚焦一个核心方法、通常 1–2 个直接步骤；同步题至少有一个非机械推理点和 2–3 个衔接步骤；挑战题必须达到 4–5/5 的结构负荷，至少落实参数或范围、区间边界或分类讨论、复合/超越结构、证明/存在性、多问联动、高阶分析中的三类，并形成三段关键推理。单选题的选项要对应不同真实误区；多选题至少两个正确项且逐项依据独立；填空题答案唯一且同步/挑战不能一步配方；解答题要给出完整分层推导。实数域上简单二次函数直接配方求顶点、一次求导或一次代入题，数学上即使完全正确也不得标成挑战。

生成任务单和服务端本地门禁必须使用同一目标难度合同。自由模型草稿的 Cherry Studio 独立审题同时检查数学与目标难度；已证明安全蓝图的 Cherry Studio 复核只从题面独立重算数学正确性、定义域、边界和唯一答案，目标难度由任务单与本地硬门单独判定，禁止把“缺少某一种方法”这类主观难度意见冒充数学错误。挑战难度的六类复杂度信号是“至少命中三类”，不是强制同时具备分类讨论、二阶导和复合函数；参数最值、恒成立等价转化、第二个参数范围判定构成的三段联动应按挑战题计算。蓝图选择先做目标难度过滤，不符合就跳过蓝图走模型起草；模型草稿进入独立审题前和独立求解后都执行同一目标难度门禁。教师、工作台与下游记录统一使用所选的 1–5 级目标等级和 `verification.difficulty_matches`。未达到目标等级时把原因送入下一次结构重试，禁止静默降档。安全蓝图还要记录 `generation.verification_policy_version` 和 `verification.scope: mathematical_correctness_only`。最终回归必须明确保证：“求最值 + 5级”不会再生成 `x^2-6x+10` 这类一步题；“求最值 + 3级 + 3题”不会再全部是填空题。
单调区间答案比较允许教材对导数为零端点使用开区间或闭区间的口径差异，只忽略对应括号类型，不忽略端点值、区间方向或函数表达式差异。带结构键的新安全题与不含结构键的旧历史记录只有在近乎完全一致（`>=0.98`）时才判重复，避免旧模板误杀不同函数族。

模型选择必须按完整草稿任务实测，不能仅凭 `flash`、`turbo` 或 `highspeed` 名称判断。测速时要求返回完整 JSON 并通过草稿完整性检查；优先选择非思考型 instruct 模型。请求使用低推理强度、草稿最多约 2800 token、复核约 2400 token 的预算，并明确禁止把试算、自我反驳或重新审视过程写入 `solution_markdown`；复核若不能简洁严格得到唯一答案，立即返回 `failed`，不要继续发散推演。若模型把预算全部用于推理并返回空正文，立即更换模型，不要反复延长页面等待时间。

## 诊断证据、任务单与结构锚点安全门

诊断证据中的每道原题必须同时满足：

- 题干、答案和完整解析齐全；图片资源存在，且没有阻断性结构质量标记或源题质量警告。带有 `source_solution_invalid`、`answer_solution_mismatch`、`solution_alignment_warning`、`answer_contamination` 或教师反馈 `solution_error` 的题不得进入安全题池、诊断证据或原题锚点。
- 标签已由教师审核，或整体置信度 `>=0.85`、主知识点置信度 `>=0.80`、分类间隔 `>=0.12`、结构置信度 `>=0.85`。
- `generation.diagnostic_evidence_question_ids` 中的 ID 必须唯一、真实存在并能解析；按学情生成时还要能关联真实作答证据。证据不足时应显示置信度不足，不得降低安全门槛凑数。
- 多题诊断只能形成 `generation.task_spec.diagnostic_profile`，包括薄弱知识、错误模式、训练缺口、已练结构与证据置信度；起草提示不得包含多道诊断题全文。

每个题位还必须满足：

- `generation.task_spec` 完整声明目标题型、目标难度、训练侧重、推理目标、必备条件、禁止结构和新颖性要求。
- `generation.structure_anchor` 恰好一个，`kind` 只能为 `mother_question` 或 `skill_blueprint`。原题锚点必须通过上述安全门并能解析到完整题目；蓝图锚点必须对应真实存在、尚未耗尽且未被拒绝的安全族。
- `generation.task_spec.generation_contract` 必须声明单全文锚点边界：普通母题路径的 `fulltext_source_question_count` 为 1 且 `use_only_one_fulltext_anchor` 为 `true`；蓝图路径的全文原题数为 0。两条路径都必须在 `forbidden` 中禁止合并多题、照抄锚点和只换数字。
- 工作台必须分别显示诊断依据数量、出题任务单和单一结构锚点；任一缺失、重复、越权或无法解析时禁止审核和加入试卷，并明确说明失败位置。

## 智能新题生成门

每道智能新题必须满足：

- 使用全新的 `question_id` 并设置 `is_generated: true`。按学情生成使用 `scope: student_practice` 和真实 `student_id`；按知识点生成使用 `scope: knowledge_practice` 和中性标识，不得伪装成某个学生的学情结果。
- 实时新生成记录使用 `generation.strategy: single_anchor_task_spec`，保存 `diagnostic_evidence_question_ids`、`structure_anchor` 和完整 `task_spec`；离线教学链候选可使用 `generation.strategy: knowledge_teaching_chain_template`，但只能作为教师端预览或迁移来源。`task_spec.schema_version` 必须为 `generation-task-spec-v2`，诊断摘要位于 `task_spec.diagnostic_profile`，提示边界位于 `task_spec.generation_contract`。这些字段仅教师可见。
- 包含完整题干、选项（如适用）、答案和解析。
- 保存 `generation.pedagogical_fingerprint`、`verification.estimated_level`、`verification.difficulty_matches` 和 `verification.answer_solution_consistency: passed`；其中任何一项缺失或不通过，都不能进入教师通过状态。
- 至少改变两个维度，且至少一个属于 `question_angle`、`condition_organization`、`representation`、`context`、`reasoning_path`。
- `verification.checked_from_stem_only: true`、`verification.answer_matches: true`、`verification.status: passed`。
- 正式打印前满足 `teacher_review.status: approved`。

旧记录兼容规则：读取 `generation.strategy: multi_source_synthesis` 时，把 `reference_question_ids` 解释为诊断证据 ID，把 `reference_count` 解释为诊断证据数量，把 `mother_question_id` 解释为单一原题锚点；若旧记录没有明确锚点，只能在教师端标为“旧版生成依据”，不得据此再次实时生成。新请求和新记录禁止继续写入 `multi_source_synthesis`，也禁止把兼容字段恢复为“多题共同构题”的语义。

运行硬校验：

```powershell
python scripts/validate_generated_questions.py "<structured-dir>" --input "<structured-dir>/generation/student_generated_question_candidates.json"
```

文本硬校验不替代语义新颖性和数学正确性的人工/模型复核。

## 教师工作台交互

- 默认界面必须遵循渐进展开：每个页签只突出一个当前任务，辅助动作收进 `工具`、`更多操作`、`更多生成设置` 或 `调整组卷要求`。功能可以被折叠，但不得被删除；现有按钮、输入和选择框的 DOM `id` 必须保持稳定，方便旧数据、脚本和浏览器本地状态继续工作。

### 原题错题集

- 导航名称必须是“原题错题集”，不要使用“新题生成组卷”。
- 卡片直接显示原题，并标明来源、班级正确率、答错人数、题型和知识点。
- 默认只暴露试卷名称、考试时间和“打印原题错题集”主按钮；含答案打印、下载方案、导出清单、恢复初始和重新生成收进“更多操作”。整套筛选放入“调整组卷要求”折叠区，展开后仍可按题型、难度数量和知识点重组选题。
- 保留逐题按题型、知识点和错误率层级换原题；这些局部控制跟随题卡展示，不挤占页面顶部工具区。
- 打印不经过新题审核门。

### 个性新题

- 默认进入“按知识点生成”，隐藏学生选择；切换“按学情生成”后才显示学生选择。知识点模式优先读取 `knowledge_practice` 教学链槽位，未实时生成的题位使用清晰等待卡片，不显示空白录题表单。
- 活跃生成区只显示本轮实时服务题和等待题位，不显示缓存候选。缓存数据只能作为内部兼容数据，不得进入当前批次、校验统计或试卷编辑区。按知识点与按学情使用不同存储键，禁止模式切换后串出旧缓存题。
- 顶部提供知识点、题型、1–5级目标等级、训练侧重和生成数量（1/3/5）；目标等级必须贯穿任务单、生成请求、校验记录和题卡展示。采用紧凑响应式条件栏，长知识点和生成按钮不得溢出。题型下拉读取 `supported_target_question_types`，不得从诊断题或结构母题的 `question_type` 自行裁剪；默认“智能匹配（批量自动分配不同题型）”。诊断证据量由系统自动确定并以只读方式展示，不作为“向模型发送几道原题”的控件。
- 默认只展示模式切换、知识点、题型、数量和“开始实时生成”主按钮；把难度、训练侧重和诊断依据说明放入“更多生成设置”，把下载方案、恢复、导出和打印放入“更多操作”。逐题条件默认折叠，避免页面纵向拥挤。旧页面仍出现 `reference_count` 时，文案必须解释为“诊断证据量”，不得显示为“综合参考原题数”。
- 每题重复提供上述控制，并提供 `通过此题`、`重新生成结构新题`、`需要修改`。再次生成按钮必须提升并持久化 `diversity_round` 和本批 `batch_size`；界面应提示优先切换未使用的严格函数族，安全族用尽后才调用 Cherry Studio 从零起草，因此后者会比蓝图换族稍慢。
- 每道题从等待、生成、独立校验到完成都必须显示实际中文题型（单选题、多选题、填空题或解答题）和明确的目标等级。选择“智能匹配”时注明“智能匹配自动分配”，教师显式选择时注明“按教师选择”；左侧题卡和右侧试卷预览使用同一题型与目标等级，禁止只显示 `auto`、`single_choice` 等内部值。每道新题下方直接展示唯一一篇“一一对应原题”；其他诊断题折叠到后台教学证据或按学情模式的后台学情证据，不得与对应原题并列造成“一题对应多题”的误解。
- 每题显示“诊断依据 N 道 · 结构锚点 1 个”。默认折叠生成依据，展开后依次显示诊断摘要、出题任务单和结构母题/安全蓝图；明确这些内容仅教师可见，并说明多题只用于诊断、不会拼成新题。
- 技术字段和编辑器放在“高级编辑与校验信息”折叠区。
- 页面主体采用左右两栏：左侧“智能生成题目”，右侧“实时编辑试卷”。独立校验通过的题可加入右侧；加入试卷视为教师选用。右侧标题区必须提供“预览模式 / 编辑模式”切换并持久记忆，默认进入预览模式：隐藏移动、删除、分值输入和 LaTeX 源码，只显示 MathJax 渲染后的学生卷题面以及可展开的渲染后答案解析。标题区同时显示“公式渲染中 / 公式已渲染 / 公式待检查”等真实状态。编辑模式显示题干、答案和解析源码以及即时公式预览；编辑后实时重渲染。右侧同时支持分值、顺序和移除，并实时保存标题、时长和题目快照。清空、下载和打印收进“试卷操作”，默认不铺开；打印和下载以右侧试卷为唯一数据源。
- 页面必须把服务链路映射成可见的五阶段进度：`多题诊断与任务单 → 单锚点草稿 → Cherry 独立求解 → 本地硬校验 → 完成`。草稿返回后立即在题卡显示新题和“独立校验中”，校验通过前禁用通过、修改和再次生成。服务端生成错误必须返回 `stage`、`error_code` 和 `retryable`；HTML 只对可重试的 422/502、超时或不完整 JSON 换结构重试，配置错误与用户取消立即停止，禁止无意义循环。
- 整套生成使用单一批次状态显示题面数、校验中、已保留数与待补位数；页面重渲染不得把进度按钮重置为 0。最多并发处理 2 道、每题最多 5 次；第 3–5 次必须明确显示“稳定补位”及当前次数，不得在后台隐藏补题。已通过题位逐题提交并保留，初轮失败题位继续补齐；最终未补齐或用户停止时只恢复失败题位原有内容，不得删除本轮已经通过并提交的题。生成中始终显示可用的“停止生成”按钮；静态预览不得执行整套生成。

## 产物

- `paper/class_paper.json`：原题错题集候选与备选，允许包含原题，必须明确 `student_visible: true` 或错题集用途。
- `paper/student_paper.json`：可直接交付的原题错题集学生版镜像；不等待新题生成或审核。
- `generation/mother_question_plan.json`、`generation/generated_questions.json`、`generation/generated_question_candidates.json`：班级新题旧链路的兼容占位，必须为 `not_applicable` 且不含题位或候选。
- `generation/knowledge_teaching_chains.json`：按知识点生成的教学链计划，包含 `prototype_consolidation`、`method_variant`、`transfer_variant` 等阶段；不依赖学生数据。
- `generation/student_mother_question_plans.json`：兼容文件名；新版本保存个人多题诊断、出题任务单和单一结构锚点，仅教师可见。
- `generation/student_generated_question_candidates.json`：兼容文件名；新版本同时包含 `scope: knowledge_practice` 的知识点教学链候选和 `scope: student_practice` 的可选学情候选。它只供教师端预览、规划迁移或展示旧记录，不进入活跃生成区和试卷；其中 `multi_source_synthesis` 不得用于新生成。
- `generation/live_personalized_generation_history.jsonl`：Cherry Studio 实时生成历史、请求条件、教师端诊断摘要、任务单、单一结构锚点和通过校验的新题；仅教师端保存，不含 API Key。
- `generation/live_personalized_generation_rejections.jsonl`：跨批次保存未通过题干、失败原因及数字无关结构，用于永久避让失败题；不进入学生题库，不含 API Key。
- `generation/teacher_quality_feedback.jsonl`：教师对原题或新题的 `solution_error`、`difficulty_too_low`、`difficulty_too_high`、`duplicate_structure` 等轻反馈记忆；后续诊断、规划、结构去重和难度门必须读取。
- `review/personalized_question_reviews.jsonl`：实时新题的教师审核状态，以 `question_id` 去重保存。
- 智能新题导出：只含已选新题；教学链阶段、诊断证据 ID、诊断摘要、任务单、结构锚点和锚点原文放在教师端生成记录，不进入学生打印内容。

## 验证

```powershell
python -m unittest discover -s tests -v
python scripts/validate_generated_questions.py "<structured-dir>" --input "<structured-dir>/generation/student_generated_question_candidates.json"
python scripts/acceptance_matrix.py "<structured-dir>" --discover 5
```

`acceptance_matrix.py` 只用于教师端/开发验收：它对隔离题库真实调用 Cherry Studio，最多并发 2 道，每题共用 1–5 次总预算，逐题提交，并输出题型、目标难度、蓝图/模型来源、复核次数和耗时；不输出 API Key。可重复传入 `--case '{"knowledge":"...","question_type":"solution","difficulty":"challenge","count":3}'` 自定义矩阵。
Windows 命令行若会改写 JSON 引号，可改用 `--case-file cases.json`；文件内容为一个用例对象或用例对象数组。

最终实际操作检查：原题错题集能直接打印原题；个性新题打开后只有等待实时生成题位；连接 Cherry Studio 后单题与整套按钮会调用实时服务；每个题位先显示多题诊断摘要和任务单，再显示恰好一个结构母题或安全蓝图；起草模型收到的原题全文不超过一份，独立复核只收到新题题面；普通题标注“Cherry Studio 模型起草与校验”，首次安全蓝图题标注“Skill 安全蓝图 → Cherry Studio 独立校验”，安全换族题标注“结构换题 → Skill 新函数族 → Cherry Studio 校验”，模型换题标注“结构换题 → Cherry Studio 起草与校验”；连续点击再次生成时函数族、数学对象或关键推理路径必须变化，忽略数字后的结构指纹不得重复；改变知识点、题型、难度或训练侧重后任务单会重建、题目会实时重新生成且审核归零；某一题生成失败不覆盖旧题，也不撤回同批已通过题；右侧题面与答案解析公式预览可随源码编辑实时更新；全部批准后个性练习打印解锁。
